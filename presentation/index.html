01 · Why this project

Learning has a weather system — and online, nobody can see it

  • Learners cycle through a small set of learning-centered states; the transitions, not just the amounts, predict outcomes (D'Mello & Graesser 2012).
  • Confusion that resolves is productive. Confusion that persists hardens into frustration — then decays into boredom, the state most damaging to learning (Baker et al. 2010).
  • A classroom teacher reads this from faces and posture. Online, the channel is severed — the instructor sees timestamps and quiz scores.

This project asks: can we restore that channel with nothing but a laptop, a webcam, and a browser?

02 · Why now — and why the browser

Three doors opened at the same time

1 · Webcam facial analysis matured

Emotion probabilities and facial action-unit intensities from ordinary video now survive "in the wild" — noisy light, real classrooms (Bosch 2015/16; Py-Feat; OpenFace 3.0).

2 · Eye tracking went JavaScript

WebGazer gives region-level gaze from a laptop camera — enough to know which panel holds attention, with no lab hardware.

3 · LLMs made tutoring real

Retrieval-grounded LLM tutoring makes the learning environment authentic — so measurement happens during real studying, not a 10-minute lab task.

And one discipline came free: capture happens on the learner's own machine — so everything captured must be justified. Privacy-first isn't a feature here; it's the entry fee.

Multimodal beats unimodal by a modest, consistent margin (D'Mello & Kory 2015) — so we fuse face + gaze + interaction, and validate channels against each other.

03 · Research questions

One measurement question, one pedagogy question

RQ1 — MEASUREMENT

To what extent can browser-based multimodal sensing — webcam facial analysis, eye gaze, interaction telemetry — detect learners' affective and cognitive states, validated against self-reported states?

RQ2 — PEDAGOGY

To what extent does an LLM-grounded platform delivering evidence-based learning-strategy interventions support learning — by learning gain, and by whether learners actually adopt the strategies?

Design principle: the two questions never touch. Interventions are only ever learner-initiated — never fired by an affect signal. So RQ1's measurements stay a clean observational layer, and RQ2's outcomes aren't confounded by detection errors. Closing that loop is the future work, not the study.

05 · How an intervention starts

Always the learner's hand on the switch

  • Highlight → generate. The learner selects a passage (the backend accepts it as grounding only at ≥ 20 chars) and picks a strategy — or uses the whole current page/slide.
  • Or accept a suggestion. The tutor chatbot may append a [SUGGEST:STRATEGY] tag when relevant; it renders as a clickable card. Nothing launches until the learner clicks.
  • Suggestion + click are both logged — so suggestion uptake is itself measurable.

VERIFIED AGAINST THE CODE

  • Only two trigger reasons exist anywhere: student_initiated, pre_generated.
  • No affective, biometric, or timer trigger path — the affect pipeline is a consumer of learning events, never a producer.
  • INTERVENTION_TRIGGERED is a log entry written after the learner's request — not a trigger.

This is the decoupling that keeps RQ1 clean.

06 · The platform — GALS

A complete tutoring environment, not a lab task

Mode B · Structured lessons

Teacher-authored courses: block pages, PDF lessons, assessments with Hattie-level feedback — read beside a docked tutor chatbot grounded on the teacher's material via RAG.

Mode A · Open dialogue

A NotebookLM-style workspace over the learner's own uploads — cited chat, study-artifact studio (briefings, flashcards, comparisons, FAQs), notes.

One retrieval pipeline under both: 512-token chunks · hybrid dense+sparse retrieval · reciprocal rank fusion (k=60) · every answer cites its source.

07 · How it grew

The build-up: five layers, in the order we built them

1 · Courseware core — auth & roles, course builder, lessons, question bank, assessments, mastery
2 · RAG + LLM tutoring — document ingest, hybrid retrieval, grounded chatbot + dialogue mode, content generation with human review
3 · The four interventions — practice testing, elaboration, stepwise, SM-2 spaced repetition + teacher prompt config
4 · Multimodal sensing — webcam recording → OpenFace 3.0 + Py-Feat, WebGazer, interaction telemetry, self-report probe, sync-anchor time base
5 · The research instrument — session replay, AOI attention scoring, EF text-mining, retrospective coding, exporters — GALS Studio

The pivot of the project: layers 4–5 weren't in the proposal. Making claims about affect forced us to build the instrument — scope evolution, not scope drift.

Our own export CSV once mislabeled the emotions "py-feat" — we found it, we disclose it, the data were always OpenFace. Pupil "diameter" is a dark-pixel-area heuristic — reported as an exploratory proxy, excluded from claims.

Deliberately not captured

  • Keystrokes → counts + speed only, never key contents
  • Clipboard → length only, never text
  • Webcam → no audio, per-course consent, 640×480
  • Passwords → redacted in any DOM snapshot
  • Element identity → coarse selectors, click text capped at 50 chars

Self-report probe: a mandatory 5-option check-in every 15 minutes — engaged · bored · confused · frustrated · neutral — the study's anchor for RQ1.

11 · The attention layer

Does the learner look where the task expects?

  • Interface panels are labeled areas of interest — sidebar, lesson/PDF, chatbot, header — captured with every snapshot.
  • Gaze samples are admitted through a validity mask (confidence ≥ 0.5, tab visible, not mid-navigation, not idle), then bucketed per panel.
  • Sessions segment into epochs — reading, intervention, dialogue — each with an expected allocation (SEEV-style expectancy–value weights).

Weights are researcher-set placeholders, so this is a relative alignment index — stated as such.

PER-EPOCH ALIGNMENT (TOTAL-VARIATION SIMILARITY)

alignment = 1 − ½ Σb | observedb − expectedb |

SESSION SCORE — DURATION-WEIGHTED MEAN

allocation_score = Σ (alignmente · Δte) / Σ Δte

One number per session in [0, 1]: how well attention followed the task. This is the behavioral reference criterion we validate facial engagement against — convergent validation, never "ground truth".

13 · LLM-assisted coding

25 dimensions per utterance, each on its own scale

Every learner utterance can be coded by GPT/Gemini across four groups — mixed response scales were a deliberate psychometric decision. Click any dimension.

← Click a dimension for its definition and scale.

Each code returns a value + ≤30-word justification citing the text; a separate pass audits whether binary is even the right scale per dimension. Nothing persists server-side — codings export to CSV beside the human codes, so coder-vs-model agreement is one join away.

14 · Where this goes

From a validated instrument to a closed loop

What stands today

A deployable tutoring platform whose every session is a time-aligned, replayable, codable multimodal record — with sensing deliberately decoupled from pedagogy.

Being validated

Facial engagement vs gaze-on-AOI (convergent), anchored by 15-minute self-reports; human coding windows vs model codes (κ, PABAK, α); pre/post parallel-form learning gain.

Next

Close the loop responsibly: offer scaffolding when validated detection sees confusion persist — intervene at persistence, not onset, because early confusion is productive.

The contribution isn't one detection accuracy — it's an honest instrument that makes learning measurable.
