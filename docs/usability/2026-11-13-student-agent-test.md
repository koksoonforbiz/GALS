# Student usability test with simulated students (2026-11-13)

Three AI agents used the student site in a real browser (Playwright), each as a different student. They ran against a local copy of the platform with the real course (_Advanced Prompt Engineering and AI Collaboration — Study Edition_) imported and set up as on the server: EF warm-up gates (T0/T2), all 18 knowledge-check gates and the item bank. No real student data was touched.

| Agent | Persona                                                              | Covered                                                                                                                                            |
| ----- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | First-year, non-native English speaker, 1366×768 laptop              | Login → finding the course → warm-up (notice, questionnaire, colour check, 7 puzzles) → pre-course knowledge check → Session 1 pre-check           |
| 2     | Engaged postgraduate, 1440×900                                       | All 26 slides of Session 1 (predictions, MCQ, reflections, Prompt Lab, chatbot, reload mid-lesson) → post-session check                            |
| 3     | Distracted, struggling student; 1024–1280 px, a phone, keyboard only | Empty answers, skipping ahead, Back/reload, idle and tab switching, asking the chatbot for answers, wrong password, sign-out, accessibility basics |

## What worked

- The whole route from first login to Session 2 works with no blocking bugs. The gates run in the right order, and the server refuses out-of-order steps with clear reasons.
- Every lesson answer saved and survived a reload. The commit-then-reveal design and the quality of the reveal text stood out.
- Knowledge checks: clean layout, Back/Next, a Review screen listing unanswered questions, and a confirmation before submitting.
- Puzzle instructions are short and plain, with friendly practice feedback. No construct names leak into the student view.
- Empty or one-word answers are refused with clear messages. Locked or invalid URLs show plain messages, never a blank page.

## Not changed (needs a decision or is environment-only)

- **Chatbot and Prompt Lab unavailable in the test copy.** The local course teacher had no LLM key, so the Lab fell back to the "Built-in template". This is environment-only; the server course has Bedrock configured. Recommended later: when no model is configured, disable Run with a banner rather than showing template output as a result.
- **1A token counter uses chars ÷ 4.** The exercise text says the counter "names the tokenizer it uses", and chars ÷ 4 undercounts JSON badly. Fix the content or use a real tokenizer.
- **Slide titles in the jump list** read "Mcq", "Selfscore", "Figure". The course import should give slides their headings. The privacy text says "working adults", but the students are undergraduates.
- **Checklist counts all 22 steps** ("2 of 22 steps done"), which reads like 22 tasks before learning. Consider counting the steps up to the next session, and listing the entry steps with durations before Start.
- **Lesson navigation:** no Next button at the bottom of long slides, ↑/↓ arrows for a left-to-right deck, and the progress bar collapses to zero width when narrow.
- **Webcam chunks** are lost when the page is navigated away mid-upload ("[Recording] Upload failed"). Worth a retry or flush on unload.
- **Label/`htmlFor` associations** on lesson textareas, tab order (the account menu comes late), and an MCQ explanation of why the right answer is right.

Screenshots and the agents' scripts were kept locally under `e2e/agents-tmp/` (not committed).
