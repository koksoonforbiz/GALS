# Rule issues (Prompt B, P4)

The Prompt A audit (CAPTURE_AUDIT.md, A6) found places where the rule code and `library.v2.json` disagree. The PI asked (2026-11-25, decision 11) to fix the ones most relevant to this study, the predefined course with the chatbot, and to record the rest here.

Fixes go into a new library version, **v2.1** (`apps/api/src/learning-events/config/library.v2_1.json`, listed under `changes`). v2 is kept and still runs: `computeSession(sessionId, set, { library: 'v2' })`. New parses use v2.1. Every detection stores its library version and the sha256 of the library file, so v2 and v2.1 results can be compared on the same sessions. Engine tests compare the two versions on the same fixtures (`engine/provenance.spec.ts`).

## Changed in v2.1

| Rule                     | Issue in v2                                                                                                                                             | v2.1                                                                                                                                                                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M34                      | Counted strategies the learner launched as uptake of a system intervention. All 30 local M34 detections came from learner-launched strategies (CAP-01). | Counts only system-initiated suggestions (`initiator = system`; older rows: `triggerReason = rule_triggered` or an experiment arm). PI decision 6.                                                                                                    |
| M34L (new)               | No measure of learner-initiated strategy use.                                                                                                           | Uptake of a strategy the learner launched: completed / viewed_only / not_taken_up within `W_seq`.                                                                                                                                                     |
| M30                      | Fired on `OUTPUT_VERIFIED` even when the learner never viewed the output.                                                                               | Needs `AI_OUTPUT_VIEWED` for the same run first. A verification without a view is left as an `UNRESOLVED` residual.                                                                                                                                   |
| M31 / M32                | Looked only at the first edit after a paste, so a small first touch-up hid a later substantive edit.                                                    | Every `OUTPUT_EDITED` on the pasted field within `W_seq` is considered; the largest edit ratio decides.                                                                                                                                               |
| M20 / M25                | The same off-task gap of at least `T_idle` got both labels, so off-task time was counted twice (CAP-71).                                                | One label per gap: `T_idle` ≤ gap < `T_break` (5 min, the session T1) is idle time (M25); a gap of `T_break` or more is an interruption (M20, also excluded from time on task). Abandonment candidates (no return) stay M20. New parameter `T_break`. |
| M05 / M24                | A low-effort prediction with no matching reveal fell between the rules: M05 skips low effort, and M24 needs a reveal.                                   | M05 keeps it as forethought with outcome `<kind>_low_effort` (`detail.lowEffort = true`).                                                                                                                                                             |
| M03b, M14, M16, M21, M28 | The code used parameters the library did not list.                                                                                                      | Listed in v2.1 at their current values (`T_read`, `W_seq`, `T_orient`, `T_out`). Behaviour is unchanged. Thresholds are now stored with every detection (`computed_values.thresholds`).                                                               |

## Recorded, not changed (research input needed)

| Rule | Issue                                                                                                                                     | Why not changed in v2.1                                                                                                                                                                                   |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M02  | The library requires `RESOURCE_SELECTED` within `W_plan` after a goal or plan; the code maps only `PROMPT_GOAL_DECLARED`.                 | `RESOURCE_SELECTED`, `GOAL_ENTERED`, `PLAN_CREATED` and `PLAN_EDITED` have no emitter. The goal card (WP5 G1, Prompt B P5) adds a goal action; whether that is planning by itself is a research decision. |

| M23  | Calibration is computed per item per session with a hard-coded ±0.25 band.                                                                | The band should become a parameter; its value is a research decision.                                                                                                                                     |

## How to compare v2 and v2.1 on stored sessions

```ts
// one session, both libraries, same parameter set
await learningEvents.computeSession(sessionId, setVersion, { library: 'v2' });
await learningEvents.computeSession(sessionId, setVersion); // v2.1, becomes current
```

Rows of both stay in `learning_events`. The last run is `is_current = true`; filter on `library_version` to compare.
