## Findings from the runs

1. **Events lost on page navigation (fixed).** The two sequence gaps above (seq 1 to 22 and 1 to 23 on two tabs, 17:13 and 17:19 UTC) are real data loss. The keepalive send on `pagehide` was cut off (`net::ERR_ABORTED`), and the next page did adopt the queue from localStorage, but a second `DurableQueue` instance on the same key (React remount) started empty and overwrote it. Fix: one queue per key per page load (`durableQueue()` in `apps/web/src/lib/capture/durableQueue.ts`), used by the activity log and the stream queues. After the fix, the interactive lesson run had an aborted batch that the next page re-sent (25 accepted, 2 duplicates), and the reruns of the knowledge-test, study-notes, capture-resilience, learner-prompt and camera-guard suites from 17:24 UTC had no gaps.
2. **`KNOWLEDGE_TEST_OPENED.sessionNo` is null for the pre-test and post-test.** The catalogue had it as required; it is now optional (the emitter is right).
3. **Camera guard events are flushed at once.** `CAMERA_BLOCKED` and `CAMERA_RESTORED` were waiting up to 30 s in the buffer; they now flush immediately, so a block that ends with the tab closing is still stored.
4. `duplicate` ingest issues are the server dropping re-sent events it already had (exactly-once by `clientEventId`); they are expected.
