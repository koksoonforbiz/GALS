**Pre-existing defects this work will hit:**

1. **A rejected batch is retried forever.** A 400 response puts the whole batch back at the head of the buffer with no drop (`ActivityLogContext.tsx:90,94`). If the web ships a new action name before the API's enum migration is deployed, every subsequent event from that tab is stuck behind the rejected batch. **Phase 2 must deploy the API and migration before the web build.**
2. **The unload flush does not clear the buffer** (`ActivityLogContext.tsx:121-138`), so every tab hide can re-POST the same events at the next flush, with fresh uuids so `skipDuplicates` cannot catch them. Learners switching to an external AI tool would make this worse. The parser (Phase 4) must de-duplicate on `(sessionId, action, occurredAt, metadata hash)`, or the bug should be fixed separately.
3. `MODULE_ITEM_VIEWED` already has **two meanings**: route-change page views (`usePageViewTracker.ts:26-35`, metadata `{path,search,summary}`) and item selection (`StudentCourseViewPage.tsx:494-502`, metadata `{itemTitle,itemType,pdfFilename}`). The parser must tell them apart by metadata shape.
4. Ten enum values are declared but never emitted, including `INTERVENTION_DISMISSED` and `SESSION_HEARTBEAT`.

- `MODULE_OPENED` is emitted at `StudentCourseViewPage.tsx:477`.

## 4. Inner-scroll caveat: confirmed

- `Layout.tsx:65,68` is `h-screen` containing `<main class="flex-1 min-h-0 p-4 overflow-y-auto">`. The course page row `StudentCourseViewPage.tsx:667` is `overflow-hidden`, and each column scrolls on its own (comment `:660-666`).
- The lesson column (`:798-801`, `data-replay-region="lesson"`) is itself `overflow-hidden`. **The actual scroll container is the per-item inner div `<div className="p-6 flex-1 min-h-0 overflow-y-auto">`** (`:809` for PAGE; also `:805, 861, 877`). It has **no ref and no data attribute**.
- The recorder notes that window scroll is "almost always 0 in the docked layout" (`useSessionReplayRecorder.ts:100-103`).

**Consequences:**

- `useSlideDwell` must take that inner div as the IntersectionObserver `root`. This needs a ref on the `INTERACTIVE_LESSON` branch's container, which is additive.
- The course HTML itself uses `root: deck` with **threshold 0.6** (`course_slides.html:251`), not the 50 % in plan §2.2 #1. Keep 0.6 for parity with the original.
- The course HTML uses `scroll-snap-type: y mandatory` with `min-height:100vh` slides (`course_slides.html:36,38`). Inside a docked column, "100vh" will be taller than the container. The Phase 1 renderer should size slides to the container (`min-height:100%`) or render one slide at a time. **One slide at a time is my recommendation:** it makes enter and exit unambiguous and removes most of the IntersectionObserver complexity.
